# ADR 002 — 应用层源码快照

状态：Accepted（0.3.0 / AXS-004）

## 决策
遍历/读取先于所有分析。SourceFile 为 frozen dataclass，content 为 bytes；分析器只接收
其解码内容，不读取源路径。快照清单以规范化 JSON 编码，ID = SHA256(清单)。清单包含
采集文件的相对路径、哈希、字节数、跳过与覆盖信息；不包含机器绝对路径和时间。
源码 blob 以内容哈希命名。清单最后写入；临时文件 + 硬链接进行不覆盖发布；重复数据
校验后复用，损坏内容报错。运行账本通过保存的报告引用 snapshot.id。

## 变化检查
单文件读取前 lstat、打开后/读取后 fstat、读取后 lstat 必须一致；采集结束再检查所有
成功读取文件。比较设备、inode、大小、mtime_ns、ctime_ns。检测到变化抛出 SourceChanged，
CLI 记录 failed/退出 2，不输出新的成功报告。旧报告如存在不会被删除，须用 run ID 区分。

## 兼容与边界
- schema v3 的 manifest 是采集文件列表；files_analyzed 仍表示成功分析文件数。
- 完整读取后语法/编码失败项有真实全文哈希；超预算/不可读取项没有伪造的全文哈希。
- 当前仅采集策略允许的 Python 文件；快照并非整个 Git 仓库归档。
- 不保证全目录同一时刻状态；新增未遍历文件、强对抗路径替换、恶意恢复元数据等不在检测保证内。
- blob 落盘不是 OS 不可修改标志：逻辑不覆盖、已有内容校验，分析实际使用不可变内存字节。
- 快照目录与输出父目录必须可信；尚未提供快照重放、垃圾回收或配额管理。
- 分析内存受采集字节预算约束，但 AST 扩张和 CPU 仍需 AXS-005 进程资源控制。

## 验证
`tests/test_snapshot.py`：内容/清单哈希、重复结果、采集变化、分析后源变化、损坏存储、
解析失败证据和不可变对象；测试只使用合成数据，不执行目标代码。
