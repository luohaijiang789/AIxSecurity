# 实施计划与阶段门禁

更新：2026-09-28。当前代码 0.8.0，当前任务是文档重整；**前端设计、Vue/Python 迁移和新增扫描能力均未在本轮开工。**
架构以 [architecture.md](architecture.md) 为准，方法以 [methodology.md](methodology.md) 为准。

精确结果见 [验收标准和历史记录](testing.md)。模型服务是外部依赖，稳定性单列，不用本地单测替代。

## 2. 决策状态

- 已明确：Java 优先、只发现/复核/报告、资产先行、人工选择后启动审计、八模块保留、Vue 前端和 Python 后端分离。
- 本方案建议：同仓模块化后端、独立 API/Worker、TypeScript/Vite、Python HTTP 框架 FastAPI；开始迁移前确认契约和依赖兼容性。
- 延后：图/向量数据库、分布式队列、多租户、多机调度；不以空目录或功能按钮冒充实现。
- Sourcebot/CodeQL 是工具候选；需单独验证固定版本寻址、许可证/分发条件、支持范围和实际精度再接入。

## 3. 阶段计划

| 阶段 | 工作与交付物 | 通过门禁 | 尚不做 |
|---|---|---|---|
| P0 文档对齐（本轮） | 单一文档导航、方法论、Vue/Python 架构、计划和验收；旧文档归档 | 无相互矛盾的“当前状态”；原始方法与八模块可定位；链接检查通过 | 页面、迁移和分析代码 |
| P1 契约冻结 | 现有 API/字段映射、目标 OpenAPI、状态枚举、错误、分页、幂等、快照与证据样例 | 成功/失败/重试/版本漂移样例通过契约测试；明确兼容策略 | 完整视觉稿 |
| P2 Worker 独立 | 抽出进程入口，API 只入队；保留现有持久任务与租约 | API 重启不终止任务；Worker 崩溃可恢复；旧 attempt 不能发布；并发领取不重复 | 分布式平台 |
| P3 Python API | 用现有用例实现版本化接口，迁移装配与项目结构 | 旧/新路径功能对照；构建/报告不在请求内执行；错误与权限边界通过 | 同时重写领域逻辑 |
| P4 Vue 功能迁移 | 独立 frontend 构建、类型化 API 客户端、资产/扫描/Case/报告/能力页面 | 真后端联调；加载、空态、失败、取消、重试、版本漂移与窄屏均验证 | 新增未经验证的扫描按钮 |
| P5 闭环与发布 | 固定真实 Java 样本，走两条生命周期；独立包/进程部署说明 | 准备不自动扫描；选择版本可追溯；模型失败可见；报告与存储一致；回归通过 | 宣称完整检出或精度提升 |
| P6 分析能力补齐 | 归一化资产 → 正式 Case → 查询适配器 → 多方法 → 精确路径/框架模型 | 每项有正反例、覆盖分母、真实样本、效果与成本对照 | 无证据 confirmed |
| P7 多仓增强 | 先集合快照/服务映射，再 RPC/MQ/HTTP 关系与跨服务路径 | 版本集合稳定；缺失边可见；传播证明逐跳可追溯 | 把同名接口当跨服务漏洞 |

每阶段一个可回退的交付增量，先评审再进入下一阶段。P6 内部先固定 Case/Evidence 契约，再扩工具，避免工具输出绑死 UI。
验收未通过时修复本阶段，不以增加界面掩盖底层缺口。

## 4. 迁移与提交规则

1. 文档与代码分开提交；本轮不提升 0.8.0 软件版本。
2. 保留现有 `src/aixsecurity` 及静态页面，迁移到 `backend/` 时单独记录路径映射、打包和 CLI 兼容变化。
3. 先增加契约及回归，再切入口；旧 UI 仅在 Vue 功能对等验收后删除。
4. 数据库 schema 迁移必须有版本和备份/恢复演练；不能以新建空库冒充升级成功。
5. Git 提交写明阶段、改动边界、测试和遗留问题；普通 push，不覆盖远端历史。
6. 构建工件、源码镜像、报告运行数据和密钥不纳入公共 Git；只提交代码、契约、文档与可公开夹具。
7. 历史设计只供追溯；新结论更新对应主文档，不继续在文末堆叠一份相互矛盾的架构。

## 5. 下一轮的唯一入口

P1 产物是接口/状态/版本契约与测试，不是继续美化旧页面。

