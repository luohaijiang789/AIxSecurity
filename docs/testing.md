## 2. 本地复现入口

从项目根目录执行：
```sh
make check
make test
git diff --check
python3 scripts/verify_java_rules.py --semgrep /absolute/path/to/semgrep
```
最后一项需要真实 Semgrep 安装；路径是待填写参数，不是已存在安装的保证。
组件测试、规则夹具、真实仓库与模型测试分别报告；不静默跳过 socket 或模型步骤后宣称全链路成功。
安装包须在项目外验证资源齐全，避免 editable/PYTHONPATH 掩盖漏打包。

## 4. 检出效果实验设计

假设：资产复用减少重复准备时间；方法互补改善覆盖；调查和复核减少误报但可能引入漏报。
在相同仓库版本与预算下分别比较：工具基线、工具+调查、工具+调查+复核、增加 Source/Sink 多方法。
保留 SQLi/命令/路径正例、负例、复杂防护、跨方法与不支持框架样本；标签不进入模型上下文。
固定样本拆分和人工裁定规则；工具、Prompt、Profile 变更不能偷偷换测试集。

测量：TP/FP/FN（以独立标签集为分母）、未决/失败数、Root/Sink 实际分析分母、未解析/未支持项、CPU/内存/磁盘、墙钟时间、模型调用/token/费用（可得时）。
候选过滤后的集合不能作为召回率分母；未调查项不能当 TN。不存在完整分母时不输出“100%覆盖”。
同一证据的多次模型赞同不作为独立样本；对复核误排单独分析。

工程硬门禁：版本一致、范围不越界、失败不发布、无证据不 confirmed、准备不自动扫描，任一违反就停止发布。
效果阈值：尚未约定具体数值；在实验前根据标签规模、预算和基线冻结阈值，不在看到结果后调低门槛。
无增益或成本过高的方法不默认启用；结论只覆盖实际验证的语言、框架与精度等级。

总成本比较使用“首次准备 + N 次审计 + 存储与更新成本”，不能只展示缓存命中的一次耗时。
