## 项目化工作流
1. 每个迭代选择一个编号；写清问题、交付物、非目标及验收条件。
2. 新功能优先使用短期分支；提交信息带编号，例如 `feat(AXS-004): add snapshot manifest`。
3. 行为变化配测试；结构性决策新增 ADR；用户可见变化进入 CHANGELOG。
4. 本地测试、项目检查、安装后 CLI 冒烟通过后提交；推送后记录 commit 和 CI URL。
5. 评审检查输入/输出契约、失败路径、数据泄漏、性能预算以及文档真实性。
6. 仅在验收完成后标 Done；远程 CI 和本地验证分别记录，不能互相代替。

## 回退与可追溯性
- Git commit 是代码版本锚点；CHANGELOG 是行为差异入口；本台账说明优化动机和完成标准。
- 已共享提交用 `git revert COMMIT_SHA` 回退，再跑测试；不重写共享分支历史。
- 报告 schema、配置 schema 和包版本分别管理；破坏兼容的行为在 changelog 写迁移说明。
- 运行账本记录执行，不替代源码版本控制；未来需要补充安装包版本与快照 ID 入账。
- 报告、SQLite、客户源码、凭据留在本地，不提交 Git；示例数据必须为合成样本。
